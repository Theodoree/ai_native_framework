# 看板「本地搜索 + 状态筛选」——筛选只活在这一层

状态：active（已落地）

## 一、为什么做

看板条目一多就只能靠滚动找。搜索与状态筛选是最省的两种收窄方式：前者按 id/标题，后者按状态。

## 二、决定

1. 筛选状态留在 `BoardView` 的 ref 里，不进 store。store 的 `items` 是后端折叠结果，把过滤后的数组写回去等于把「看不见」变成「不存在」——详情面板、流转、验证、同步全会跟着断。
2. 搜索只按 id 与标题做大小写不敏感子串匹配，不做防抖、不做模糊、不搜正文：需求只到这里，加宽会改语义。
3. 状态筛选用 `(string | null)[]`，`null` 表示「状态为 none」。不用字符串 `"none"` 当哨兵——声明里真的可以有一个叫 none 的状态。
4. 筛选条只列**看板里出现过的状态**并带计数；声明了但 0 条的格子不给入口（点了只会得到空屏）。
5. 不筛选时保留空列（列由声明决定，是看板结构）；一旦筛选就收掉空列，否则命中一条也要横排九格「空」。
6. 两种空态必须分开：一条都没有（数据问题）与全被筛掉（筛选问题，附「清空筛选」回头路）。
7. 「全部」chip 只清状态、不动搜索词：两个条件各自要能单独退。

## 三、放弃了什么

- 不抽 `BoardFilterBar.vue`：只有一处使用，抽出去要为一个 ref 组做 props/emit 管道，纯增噪。
- 不把筛选放进 store computed：只有一处在读，等于给展示态找一个假的全局家。
- 不给 web-vue 加单测：该包没有 vitest 配置，加基建等于新增依赖；逻辑是纯展示推导，靠 typecheck/build/真机验证覆盖。
- 不在筛选时自动清空 `selectedId`：会让人莫名丢掉正在看的条目。

## 四、怎么验的

临时后端（`PLATFORM_LEDGER` 指到 /tmp）+ 四条不同状态的条目，ego-browser 驱动真页面：
`显示 4 / 4` → 搜 `board` 得 `显示 1 / 4` 只剩 REQ-2、列收成一列 → 点 accepted chip 得 `显示 2 / 4` 只剩 REQ-3/REQ-4 → 点「全部」回 4/4 九列 → 搜 `zzz` 得 `显示 0 / 4` 与「没有匹配的条目：4 条全被当前筛选排除了。」→ 点「清空筛选」回 4/4。

## 五、仍然没有的（刻意）

- 不搜正文、不高亮命中片段、不做分页/虚拟滚动。
- 筛选条件不落到 URL，刷新即回全部。

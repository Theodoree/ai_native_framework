# P-07 门牌幂等重算

- **日期**：2026-10-20
- **状态**：implemented（机制侧已落地；真 PR 上的重算待有第二个 PR 时验收）
- **里程碑**：M2 · 门与门牌
- **依赖**：P-03

## 背景

`docs/last-change.md` 规定门牌是派生数据、由 CI 幂等重算、取后合并者。现在没有任何 job 在做这件事，而 merge gate 的第 4 条守卫依赖门牌含本 PR 编号。

## 目标 · 验收 · 边界

- **目标**：PR 的 LAST-CHANGE 表始终是重算结果，同一份输入重算两次得到同一答案。
- **验收**：同一条 PR 触发两次重算，两次表格内容逐字相同（`git diff` 为空）；合并后合并人/合并日期被补写；两次 PR 改同一模块时按「后合并者」得到结果，不产生人工冲突。
- **边界**：可动 `.github/workflows/`（新增 job）、`scripts/`（新增重算脚本）、`tests/`。不动 PR 模板。

## 放弃了什么

- **手写门牌清单**：门牌、issue 状态、PR 描述三处各记一份，必然有一处过期。

## 落地记录

- **幂等的根是「没有时钟」**：脚本里没有 `Date.now()`，合并日期只从事件的 `merged_at` 取 UTC 日期。时间一旦由脚本自己决定，同一份输入两次重算就会不同，判据当场失效。
- **边界用标记而不是标题定位**：`<!-- LAST-CHANGE:BEGIN/END -->` 让重算整段覆盖。仅靠 `## LAST-CHANGE` 标题定位时，节内残留的冲突标记会被当成正文保留下来。
- **「还没发生」写「—」而不是留空**：空白分不清是「没值」还是「算坏了」，而门牌的全部价值在于它是机器读的。
- **校验全过才算完 + 原子落盘**：合并人来了一半（只有 `merged` 没有 `merged_at`）时整次重算 exit 1，文件 sha 前后相同——「补写失败不影响已有字段」是这么保证的，不是靠 try/catch。
- **写回是条件写**：`changed=0` 时不 `gh pr edit`。否则 `edit` 事件触发自己，形成自激循环；这条被 wiring 测试直接钉住。
- **改契约的那一句（`docs/last-change.md` 第五节）**：契约只写「提案（或修复）文件」，两个 PR 模板却分别叫「修复文件」「提案文件」。重算不猜 PR 类别，就必须有唯一行名，于是统一叫「变更文件」——这是契约空白，不是实现偏好。
- **审核人取 `requested_reviewers`**：这是宿主唯一给出的 review 信号；没人指派写「—」，提交 review 后重算会更新。

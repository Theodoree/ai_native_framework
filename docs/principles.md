# principles.md · 准则与理由（给人读）

> 框架（`AGENTS.md`）只写**指令**；**理由集中在本文件**——人判边界需要理由，agent 执行只需要指令。
> 本文件**不进常驻上下文**：按需查阅即可。

## 质量

**定义**：质量 = 可验证的行为符合预期。

**理由**：读代码只能得到"看起来对"，只有可重复运行的检查才能得到"确实对"。测试是**机器可验证**的闸门；人的 review 只做补充——review 会累、会漏、会随上下文漂移，闸门不会。

## 按使用频率分层

**理由**：**上下文稀缺**。常驻的每一行都在**每次会话**里重复付费，所以按使用频率分层——常用的留短、少用的外置、用完即弃的不落盘。

## 一个事实只有一个家

**理由**：**文档重复 = 腐化源**。同一事实写在两处，改一处忘另一处，两份会分叉；读者也不知道该信哪个。

## 变更必须自我记录

**理由**：**agent 之间没有对话记忆**。上一个 agent 的取舍若不写下来，下一个 agent（或同一个人隔一周）只能重新推导一遍；**团队并行时尤其如此**。

## 规则只能由人定

**含义**：约束 = 会改变后续产出的判定条件（门、阈值、必须满足的前提）。约束的正当性来自**被同意**，不来自**被写出**。

**理由**：一条约束会持续改写所有后来的走向，而自造它的执行者不为结果承担后果——既写规则又打分的人同时是选手和裁判，约束就从共识变成**伪装成共识的偏好**。两个隐蔽危害：自造的常数（体积上限、依赖数量）看起来和仓库既有规则一样权威，后来的人分辨不出哪条被谁批准过；而它一旦成为门，反驳它的人要先证明它是假的，成本落在别人身上。因此允许提议、要求指出来源、确认前不判通过——**提议是执行者的职责，落地是人的权力**。

## 提交格式（Conventional Commits）

**理由**：`feat:` / `fix:` / `docs:` 这类前缀是**机器可解析**的——用它就能**自动生成 CHANGELOG**，不必靠人记得写。所以类型必填、subject 用祈使句。

## FAT（约束不得引用代码逻辑）

**含义**：FAT = 把**长度不可控**的东西塞进了约束/提示词。

- **可以引用**：长度确定的**文档**——`docs/architecture.md`、模块 `README.md`、`.agents/notes/` 里的决策记录。长度可预算，能整份读进来。
- **不得引用**：**代码**——文件路径、行号、函数/类名。代码长度不可控：今天 200 行，明天 2000 行，读它就把上下文撑大。
- **后果**：上下文被撑大后，**压缩时最先被丢掉的正是约束本身**——你花代价写下的规则，在执行时反而不存在了。
- **正确形态**：约束要**简单、明确、可直接命中**——写成可判定的指令，而不是"去看某个文件的某个函数"。

## 准则的定律来源

框架保留能**直接执行**的那几条（第一性原理 / 奥卡姆剃刀 + YAGNI / 阿姆达尔定律 / 墨菲定律）；定律名、含义与出处留在这里当参考点。

| 定律               | 含义                                   | 由它得到的指令（已进框架「准则」）                          |
| ------------------ | -------------------------------------- | ----------------------------------------------------------- |
| 第一性原理         | 从不可再分的本质事实倒推，不模仿现状   | 设计前先问：本质约束是什么？最简路径是什么？                |
| 奥卡姆剃刀 + YAGNI | 如无必要勿增实体；现在不需要的功能不做 | 新增抽象/模块/配置/技能前，先证明现有方案无法满足；否则砍   |
| 阿姆达尔定律       | 加速比受**未被优化的那部分**限制       | **优化热点代码**：先优化占大头的部分（热点代码 / 热点路径） |
| 墨菲定律           | 会出错的事总会出错                     | 先跑验证，再读代码；没有通过的检查，不算完成                |

**已剔除的三条（对 agent 无用）**：

- **康威定律**（系统架构追随组织结构）—— 讲的是组织形态，不是 agent 的动作；
- **布鲁克定律**（给落后的项目加人会更慢）—— 同为组织建议，且**阿姆达尔已覆盖"别靠堆并行"**这一面；
- **帕累托原则**（80% 价值来自 20% 工作）—— **与阿姆达尔重复**：都指向"把力气花在占大头的那部分"。

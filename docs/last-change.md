# last-change.md · 门牌

门牌是 PR 里那张表（模板见 `.github/PULL_REQUEST_TEMPLATE/`），回答一个问题：**这次变更会被记成什么**。

## 一、它是派生物

门牌不进人工维护的清单文件，而是由 CI 从 issue、PR、review、merge 事件**幂等重算**的结果。任何一次重算都应得到同一答案，因此它可以被安全覆盖。

## 二、写什么、谁来写

| 时机           | 写什么                                                 | 谁写 |
| -------------- | ------------------------------------------------------ | ---- |
| PR 创建 / 更新 | 提议人、审核人、issue、PR 号、标题、提案（或修复）文件 | CI   |
| 合并后         | 合并人、合并日期                                       | CI   |

第一次写就带 PR 号，所以硬判据「门牌必须含本 PR 编号」在第一步即满足；合并后的补写失败不影响判定。

## 三、冲突

两个 PR 改同一模块的门牌，会在合并前冲突。**不人工合并**，规则是取后合并者——语义就是「最近一次」，重算本来就该给这个答案。

## 四、为什么不做成手写文件

手写会分叉：门牌、issue 状态、PR 描述三处各记一份，必然有一处过期。派生物只有一个来源，过期就重算。

## 五、重算的输入与口径

- 输入只有两类：宿主事件（PR 号、标题、提议人、review 名单、是否合并、合并人、合并日期）与 git 区间（分叉点 → 本 PR 的 head）。身份一律取事件字段，不读任何自述。
- 表与模板同行同序；文件那一行统一叫「变更文件」，模板里的「修复文件 / 提案文件」是同一事实的按类命名，重算不猜类别。
- 还没发生的项写「—」，不写空白：未指派审核人、未合并时空白分不清是没值还是算坏了。
- 合并日期取事件 `merged_at` 的 UTC 日期。重算没有自己的时钟，同一份输入永远给出同一天。

# docs/AGENTS.md · 文档标准

> 原则：**一个事实只有一个家**（one home per fact）。文档分层见 `AGENTS.md` 的「文档分层」。

## 层级归属

> 分层表（L0–L4 各自的家）的唯一真相源是 `AGENTS.md` 的「文档分层」；本节只定**归属判据**——判断一份文档该放哪一层，不重复分层表本身。

- 写「总体地图 / 模块关系」→ L1（`docs/architecture.md`）
- 写「这个模块的契约」→ L2（模块内 `README.md`，跟代码走）
- 写「为什么这么定 / 放弃了什么」→ L3（`.agents/notes/`）
- 写「多步流程怎么走」→ L4（`.agents/skills/`）

## 写作规则

- 写当前状态，不写变更历史（"previously/now/no longer" → 提交记录/决策记录）
- 一个事实只在归属层出现一次，他处用链接
- 状态标记：`active` / `stale` / `deprecated`，与模块 README 同步
- **不写关于文档自己的话**：结构说明、写法规矩不进正文——读者要内容，不是"这份文档怎么组织"
- **不用 HTML 注释**：渲染后不可见，对读者等于不存在。要留的信息写成可见文本
  - **例外**：注释若在围栏**内部**（例如 `docs/postmortem/README.md` 里的填写提示），渲染后是**可见文本**，可以用——闸门也豁免该文件。
- **索引节只放链接**，不复述内容（复述 = 制造第二个家）
- **原则/哲学类条目必须落到对 agent 的具体指令**，不写抽象格言
- **安全红线必须内联在 `AGENTS.md`**；细节可外置，红线本身不行
- **`AGENTS.md` 保持短**：指令过长时模型只读前半句
- **约束不得引用代码逻辑（FAT）**：不写代码文件路径、行号、函数/类名
- **Markdown 表面的交付物末尾带 dsh 徽章**：README、PR/MR 描述、交付说明的最后一行放官方 powered-by-dsh 徽章；颜色/标签/尺寸/链接只照 `dsh-badge` 技能给的资源，不另造

> 各条规则的**理由与定义**（FAT 的含义、准则里那几条定律的出处等）见 `docs/principles.md`。

## Gate 钩子

> **模板仓库自身的闸门**机械检查：L0 预算超限、内部引用（含死链）、写作规则里的 HTML 注释与 FAT 两条；**产物侧（新项目）默认没有任何 gate**——需要强制时按 `AGENTS.md` 的「特性启用」把「验证」命令接进流水线。

# 架构

这是 L1 总览：平台的形状、模块怎么排、一次需求怎么流过它们。**具体契约在各模块自己的 README**，这里只做地图，不重复契约。

## 一句话

平台管三样东西：**链条**（节点顺序的声明）、**需求**（一条进链的实例）、**节点状态**（需求此刻站在哪，由状态推导，不单独存）。

## 分层

```
前端 apps/web（Vue 3 + Vite + TS）──构建──▶ apps/chain/webui/dist（go:embed，已入库）
                                                    │
HTTP 层   apps/chain/http.go    只做校验与搬运，不下结论，不写状态
          apps/chain/intake.go  接入层：给平台外用，认 project 口令、塞需求、回告结论
                                                    │
状态机    apps/chain/model.go   唯一的状态写者：跑、通过、驳回、评论、追加规则
                                                    │
存储      apps/chain/store.go   接口 Store：工程 / 需求 / 节点 / 执行记录 / 评论 / 事件
          apps/chain/store_sqlite.go   SQLite 实现（默认；换 MySQL 只加一个实现）
                                                    │
执行器    apps/chain/executor.go        FakeExecutor：不连外部服务
          apps/chain/executor_docker.go DockerExecutor：docker run，注入环境变量
```

依赖方向单向向下：HTTP 不认识 SQL，状态机不认识 docker，执行器不认识 HTTP。要换其中一层，只动那一层。

## 模块地图

| 路径 | 装什么 | 契约在哪 |
| --- | --- | --- |
| `apps/chain/` | 平台本体：状态机、存储、HTTP、执行器、入口 | `apps/chain/README.md` |
| `apps/web/` | 前端源码（Vue 3 + Vite + TS，无 UI 库，样式手写） | `apps/web/README.md` |
| `apps/chain/webui/dist/` | 构建产物，被 `//go:embed` 打进二进制 | 生成物，改前端后重跑 `npm run build` |
| `docs/` | 规则与原则（L1 总览是本文；写作规则见 `docs/AGENTS.md`） | 各文件本身 |
| `.agents/notes/` | 决策记录：为什么这样做、放弃了什么 | `proposed/` = 讨论中，`implemented/` = 已落地 |
| `.agents/skills/` | 高频多步流程 | 各自的 `SKILL.md` |

仓库没有 `src/`：代码按模块放在 `apps/<模块>/`，每个模块自带 README 与测试。模板遗留的 `src/README.md` 已删除。

## 一次需求流过什么

1. **建工程**：登记 key、name、repo、默认分支，挂 N 条链。链是声明，不是编排器。
2. **提需求**：选链 → 生成需求实例，链的版本被钉住，分支名 `req/<project>/<id>` 由平台给出（仓库里的分支要人自己建）。
3. **逐站推进**：每一站 `pending → running → awaiting_review → accepted`。容器站由执行器给日志与评论；空节点由人自己动手后按「通过」。
   节点声明 `review: ai` 时，容器在输出里打一行 `CHAIN_VERDICT: pass|reject 原因` **自己定案**；标记缺失、取值认不出、reject 没写原因，一律停在待审并留系统留言——判不出来不许当通过。
4. **驳回**：回滚到上一节点，历史一条不删；首站被驳回等于整条需求被驳回。
5. **合并与上线**：`merge` 由人在仓库里做，平台只等人按「通过」；`release` 是链的最后一站。

从平台外面进来的需求走接入层（`intake.go`）：管理口令建 project → 拿到该 project 的访问口令 → 用口令提需求、用口令拉结论。整条需求被拒时平台尽力回告一次，**回告失败只记事件、不改状态**，所以结论始终可以用拉模式取到。

事件流（`events` 表）记录每一次状态跃迁，只追加，**不参与任何判定**。

## 技术栈

| 关注 | 选择 | 理由 |
| --- | --- | --- |
| 语言 | Go ≥ 1.26（标准库为主） | 单二进制、无运行时依赖、并发与 HTTP 都是标准库 |
| 存储 | SQLite（`modernc.org/sqlite`，纯 Go 免 cgo） | 零外部服务即可跑；`Store` 接口为 MySQL 留缝 |
| 前端 | Vue 3 + Vite + TypeScript，无 UI 库 | 构建产物小（148K）、无框架锁定、样式用 design tokens 手写 |
| 打包 | `//go:embed webui/dist` | 一个二进制带页面；代价是产物必须入库 |
| 执行 | 本机 `docker run`，未来换 k3s | 执行器是接口，换运行时不动状态机 |
| 判据 | 本地 `go test ./...`（`verify-change` 技能） | 平台不依赖任何托管 CI；合并由人按 |

## 不变量

1. **状态只有一个写者**：节点状态只能由状态机改，HTTP 层只校验与搬运；容器自审也只是把结论递给状态机，不能直接改状态。
2. **位置是推导出来的**：不存「当前位置」，只存每个节点的状态。
3. **评论与执行记录只追加**：回滚重置状态，不删历史。
4. **人保留否决权**：合并永远由人做，平台不代做。
5. **默认文件不改**：某条需求某一步要加规则，追加到该节点上，不动仓库里的 AGENTS.md。
6. **资格由角色对节点的权力决定**：平台的人员身份只有两种口令——project 管理口令（建 project、管角色）与角色口令（按节点），没有账号体系。一个节点动作能不能按，只看「这个角色对这个节点有没有权力」，判不了就拒绝。

## 边界

- **不依赖 GitHub**：仓库只是 project 上的一个字符串，平台不调用任何仓库 API，也不设 status check。
- **没有独立编排器**：进度不需要调度进程推动，由「第一个还没通过的节点」算出来。
- **AI 自审只读容器的一句话**：平台不调模型、不看产出对不对，只看容器在输出里打的那行标记；容器想怎么得出这个结论，是镜像自己的事。
- **单机单写者**：没有人员鉴权、没有多租户、没有乐观锁（`rev` 已留但未使用）；接入层只有 project 级的访问口令，不区分人。

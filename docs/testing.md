# testing.md · 测试策略

> **测试位置按语言习惯**：TS/Rust 就近（与实现同目录），Python 集中（`tests/`）。
> **断言强度**：一条测试只断言一个行为；失败信息能直接读出期望与实际；禁止用「不抛异常」充当断言。

## 强制测试范围

「测试是可选的」会让核心模块无测试也能合，且门牌里查不出谁测过。改为**按模块声明**：`OWNERS.md` 的模块表有一列 `强制测试`，取 `yes` 的模块改一行就必须有对应测试，否则 PR 不进审计。

两类模块一律 `yes`：改了就影响交付链判定的（状态机、校验器、审计契约、merge gate），和改了就影响新项目产出的（`scripts/init.sh`、技能里的脚本）。

## 正控

校验类逻辑必须有正控四件——**去掉断言后测试仍会红**：

1. 合法输入通过；
2. 越权输入被拒并说明原因；
3. 配置缺失 / 状态名拼错报 INFRA（不许当通过）；
4. 同一对象出现两个状态标签时报错。
